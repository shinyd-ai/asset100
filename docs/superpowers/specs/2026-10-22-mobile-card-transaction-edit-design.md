# 모바일 카드내역 수정 설계

**작성일:** 2026-10-22  
**상태:** 사용자 검토 대기

## 1. 목적

휴대폰에서 카드 거래의 가맹점, 카테고리, 자금그룹을 빠르게 수정하고, 필요한 경우 금액·메모·할부·날짜도 수정한다. 수정값은 저장 버튼을 누를 때만 반영한다.

## 2. 확정된 사용자 경험

### 단건 수정

1. 거래 행을 누른다.
2. 화면 하단 편집 시트에서 가맹점, 카테고리, 자금그룹을 수정한다.
3. `상세 항목`을 펼치면 금액, 메모, 할부, 날짜를 수정할 수 있다.
4. 수정값은 기기에만 임시 보관되고, 행에는 `수정됨` 상태가 표시된다.
5. 하단 고정 저장 버튼을 누르면 모든 임시 수정을 한 번에 반영한다.

### 여러 건 수정

1. 상단의 `선택`을 누르면 선택 모드로 전환한다.
2. 거래를 여러 건 선택한다.
3. 하단 고정 영역에서 카테고리와 자금그룹을 선택한다.
4. 선택된 항목에만 두 값을 일괄 적용하고 저장 전까지 임시 보관한다.

여러 건 수정은 가맹점, 금액, 메모, 날짜, 할부를 수정하지 않는다.

## 3. 연결 및 동기화 규칙

| 연결 상태 | 표시 | 저장 동작 |
| --- | --- | --- |
| 결제 메일 연결 | 봉투 체크 아이콘 및 연결 건수 | `card_tx`만 수정 |
| 가계부 거래 연결 (`budget_id`) | 연결 고리 아이콘 | 날짜, 가맹점, 카테고리, 금액, 메모를 연결된 `budget`에도 같은 값으로 반영 |
| 수동 분류 (`category_locked`, `fund_group_locked`) | 핀 아이콘 | 수정 가능. 저장한 값은 수동 분류 상태로 유지 |
| 연결 없음 | 아이콘 없음 | `card_tx`만 수정 |

`category_locked`와 `fund_group_locked`는 수정 금지가 아니다. 자동 분류가 사용자의 값을 덮어쓰지 않도록 하는 수동 선택 표시다.

가계부에는 자금그룹·할부 필드가 없으므로 이 두 값은 `card_tx`에만 저장한다. 결제 메일 연결(`card_payment_links`)도 메타데이터이므로 거래 편집 중 변경하지 않는다.

## 4. API 설계

### 조회

기존 `GET /api/card-tx`를 계속 사용한다. 응답에는 이미 `linked_payment_count`가 포함된다. 모바일 UI를 위해 아래 필드를 추가한다.

- `budget_linked`: `budget_id IS NOT NULL`
- `category_locked`, `fund_group_locked`: 기존 필드를 그대로 사용
- `fund_group_name`: 자금그룹 표시명

### 일괄 저장

`PUT /api/card-tx/bulk`를 추가한다.

요청 예시:

```json
{
  "changes": [
    {
      "id": 101,
      "base": {
        "name": "기존 가맹점명",
        "category": "기존 카테고리",
        "fund_group_id": null
      },
      "fields": {
        "name": "가맹점명",
        "category": "식비",
        "fund_group_id": 3,
        "amount": 24500,
        "memo": "상품명: 원두",
        "installment": 1,
        "date": "2026-09-01"
      }
    }
  ]
}
```

서버 처리:

1. 요청 형식, 거래 존재 여부, 날짜, 금액, 할부, 자금그룹 유효성을 모두 검증한다.
2. 각 변경 항목의 `base` 값과 현재 DB 값을 비교한다. 사용자가 편집한 필드가 저장 대기 중 바뀌었다면 `409` 충돌 오류를 반환한다.
3. 오류 또는 충돌이 있으면 어떤 DB 행도 수정하지 않고 행별 사유를 반환한다.
4. 모두 유효하면 하나의 DB 트랜잭션에서 `card_tx`를 갱신한다.
5. `budget_id`가 있는 항목은 변경된 날짜·가맹점·카테고리·금액·메모를 `budget`에도 갱신한다.
6. 성공 응답에는 수정 건수와 동기화된 가계부 건수를 돌려준다.

응답 예시:

```json
{
  "ok": true,
  "updated": 3,
  "budget_synced": 2,
  "rows": []
}
```

기존 `PUT /api/card-tx/<id>`는 데스크톱 그리드 호환성을 위해 유지한다. 모바일 화면은 새 일괄 저장 API만 사용한다.

## 5. 프론트엔드 구조

데스크톱 `GridTable`은 유지한다. 카드내역 탭에 모바일 전용 프레젠테이션 레이어를 추가하고, CSS 미디어 쿼리로 작은 화면에서만 보인다.

### 상태

- `mobileRows`: 서버에서 조회한 현재 거래 목록
- `draftChanges: Map<transactionId, partialFields>`: 저장 전 수정값
- `selectionMode`: 다건 선택 모드 여부
- `selectedIds: Set<transactionId>`: 선택 거래
- `sheetTransactionId`: 열려 있는 단건 편집 시트의 거래

원본 행과 임시 수정값을 합쳐 화면을 표시한다. 저장 성공 전에는 그리드를 다시 불러오지 않는다.

### 저장 전 요약

저장 버튼 또는 확인 시트에는 다음을 표시한다.

- 수정 거래 수
- 변경할 항목 요약
- 가계부 동기화 예정 건수

저장 완료 후 `GET /api/card-tx`로 다시 조회하고 `N건 저장됨 · 가계부 N건 동기화`를 표시한다.

## 6. 모바일 레이아웃과 표현

```text
[카드 · 기간 필터] [선택]
────────────────────────
[연결 아이콘] 가맹점명              금액
              카테고리 · 자금그룹     날짜
────────────────────────
                 … 거래 목록 …

수정 내용 3건                         [저장]
```

- 행 전체가 단건 편집 시트의 진입점이다.
- 가맹점 옆에 연결·핀 아이콘을 표시하고, 아이콘에는 접근 가능한 설명을 제공한다.
- 금액은 오른쪽 정렬과 굵은 글꼴로 표시한다.
- 최소 터치 영역은 44px이다.
- 바닥 저장 영역은 화면에 고정한다.

### 디자인 토큰

| 용도 | 값 |
| --- | --- |
| 배경 | `#F7F8FA` |
| 본문 | `#1F2933` |
| 주요 동작·선택 | `#146C94` |
| 저장 대기·주의 | `#B45309` |
| 오류·삭제 | `#B42318` |

## 7. 오류와 이탈 처리

- 검증 오류나 네트워크 오류가 나면 `draftChanges`를 유지한다.
- 행별 서버 오류는 해당 행과 편집 시트에 함께 표시한다.
- 저장 충돌이 나면 최신 서버값과 사용자의 임시값을 해당 행에서 비교해 보여주고, 사용자가 다시 선택하도록 한다.
- 기간·카드 필터 변경, 탭 이동, 화면 이탈 시 저장하지 않은 변경이 있으면 확인을 요청한다.
- 저장 중에는 저장 버튼을 비활성화하고 진행 상태를 표시한다.

## 8. 구현 검증

### 성공 기준

- 360px와 390px 너비에서 거래 목록, 편집 시트, 하단 저장 영역을 조작할 수 있다.
- 단건 수정은 저장 전 DB를 바꾸지 않는다.
- 여러 건 카테고리·자금그룹 수정은 선택한 행만 변경한다.
- 하나의 저장 요청으로 모든 수정이 저장된다.
- `budget_id` 연결 거래의 공유 필드는 `budget`에도 동일하게 반영된다.
- 메일 연결 수와 연결 레코드는 거래 편집 후에도 유지된다.
- 데스크톱 GridTable의 생성·편집·삭제 흐름이 유지된다.

### 실패 기준

- 일부 행만 저장되는 경우
- 카드내역과 연결된 가계부 거래의 공유 값이 달라지는 경우
- 서버 오류 때 임시 수정이 사라지는 경우
- 저장 대기 중 갱신된 거래를 사용자 확인 없이 덮어쓰는 경우
- 다건 수정으로 가맹점·금액·메모가 변경되는 경우
- 기존 데스크톱 편집이 깨지는 경우

### 검증 방법

1. 단건·다건 성공 저장을 API와 화면에서 확인한다.
2. 잘못된 금액, 날짜, 자금그룹으로 일괄 요청을 보내 전체 저장이 취소되는지 확인한다.
3. 저장 대기 중 한 거래를 다른 요청으로 갱신한 뒤, 일괄 저장이 충돌로 취소되는지 확인한다.
4. `budget_id`가 있는 거래와 없는 거래를 함께 저장해 동기화 건수를 확인한다.
5. 결제 메일 연결과 수동 분류 아이콘을 가진 거래에서 표시와 데이터 보존을 확인한다.
6. 360px, 390px, 데스크톱 너비로 수동 반응형 점검을 한다.

## 9. 범위 밖 항목

- 카드사 또는 뱅크샐러드 API 연동 방식 변경
- 카드내역 삭제 흐름 변경
- 가계부 데이터 구조에 자금그룹·할부 필드 추가
- 카드 결제일 또는 청구일 계산 규칙 변경

## 10. 시각 디자인 보완안

### 목표

기능 버튼을 늘리지 않고 거래 행, 분류 정보, 저장 상태의 위계를 분명하게 만든다. 기본 Bootstrap 카드와 외곽선이 반복되는 인상을 줄이고, 차분한 금융 앱의 밀도로 정리한다.

### 화면 구성

1. 상단에는 카드·기간 필터와 작은 검색 아이콘만 둔다.
2. 월간 카드 사용액은 하나의 짙은 청록 요약 영역으로 표시한다.
3. 거래는 흰색의 낮은 밀도 행으로 표시한다. 가맹점·연결 아이콘은 왼쪽 위, 분류 칩은 왼쪽 아래, 금액·날짜는 오른쪽에 둔다.
4. `선택`은 텍스트 버튼으로 유지한다. 저장은 하단 고정 영역의 청록 버튼 하나만 강조한다.
5. 거래를 누르면 둥근 모서리의 하단 편집 시트가 열린다. 가맹점, 카테고리, 자금그룹을 먼저 보이고 상세 항목은 접어 둔다.

| 용도 | 값 |
| --- | --- |
| 앱 배경 | `#F4F6F8` |
| 본문 | `#17212B` |
| 주요 저장·강조 | `#126B73` |
| 카테고리 칩 | `#E5F3F1` |
| 자금그룹 칩 | `#F5ECDF` |
| 구분선 | `#E7EBEF` |

### 구현 제약

- 기존 API, 저장 방식, 연결·수동분류 아이콘의 의미는 변경하지 않는다.
- 모바일에서만 새 시각 구조를 적용하고 데스크톱 GridTable은 유지한다.
- 모바일 거래 행과 모든 조작 요소는 44px 이상의 터치 영역을 유지한다.
- 색상만으로 연결·수동분류 상태를 구분하지 않고 아이콘의 접근성 이름을 유지한다.
